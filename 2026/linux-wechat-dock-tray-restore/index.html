Linux 版微信关掉窗口后点 Dock 图标没反应？摸清它的托盘激活逻辑，写个包装脚本彻底解决

本文内容由 AI 生成，并已人工验证可信。

在 Ubuntu 上用微信，有个很别扭的毛病：点了窗口右上角的关闭按钮，微信就缩到顶栏托盘里去了，进程还在、消息照收。这时候你想把它叫回来，下意识去点左边 Dock 栏的微信图标——结果鼠标变成转圈，转了几秒，什么也没发生。窗口不回来，只有老老实实去点顶栏那个绿色托盘图标才行。

这个毛病我忍了很久，网上能搜到的答案基本都是「改习惯，点托盘」。索性把它彻底扒了一遍，最后用一个包装脚本解决了，现在点 Dock 图标和点托盘效果完全一样。

先说结论

  • 微信关窗口只是 hide()，进程和窗口对象都还在，托盘图标也还挂在 D-Bus 上；
  • 点 Dock 图标时，GNOME 会重新执行一遍 desktop 文件里的 Exec，也就是再跑一次 /usr/bin/wechat。微信有单实例锁，第二个进程 0.04 秒后以退出码 255 静默退出，什么也不做——于是既没有窗口，也没有报错，只剩下一个转圈的鼠标；
  • 真正能把主窗口叫回来的，只有微信自己注册的托盘项（org.kde.StatusNotifierItem）。它的 Activate 方法和托盘菜单里的「显示」项才是「恢复主窗口」的正确入口。

所以解法就是：别让 Dock 图标再去跑 /usr/bin/wechat，让它先走托盘那条路。

排查过程

一、微信根本没退出

关掉窗口以后看进程：

主进程、crashpad、小程序运行时、各种 renderer 一个不少。/usr/bin/wechat 其实是 /opt/wechat/wechat 的软链接，整个东西是一套基于 Qt 的自绘界面，主窗口是 Wayland 原生 surface（libwayland-client.so 在它的内存映射里，X11 的窗口树里找不到它）。

这就解释了第一件事：它不是崩溃，也不是最小化。最小化的窗口在 GNOME 里点 Dock 图标是能还原的，因为它还挂在窗口管理器上；而隐藏起来的窗口对 shell 来说等于不存在了。

二、点 Dock 图标，其实是在重复启动微信

GNOME 这边呢？它只知道「我执行了 Exec，进程退出了，但没有窗口出现」。配合 desktop 文件里的 StartupNotify=true，它还在等一个永远不会到来的启动完成信号——你看到的那个转圈的鼠标，大概率就是在等这个。

顺手记一笔：既然第二个实例是静默退出的，「再点一次 Dock 图标」这种土办法在 Linux 上没有任何用，只有第一次点的时候可能碰巧有效。

所以现象完全对上了：托盘能恢复，Dock 不能，因为两者调的根本不是同一段代码。Dock 那边压根不知道「微信已经有窗口了」，它只会傻傻地重跑一遍启动命令。

而这两个入口都会被我写进下面的脚本里，谁生效都行。

解决方案

思路：给 Dock 图标换一个 Exec。微信已经在跑，就走托盘那条路；没在跑，才真正启动。

1. 包装脚本

几个设计取舍说明一下：

  • pgrep -x wechat -o 只取最早的那个 PID，也就是主进程，避免匹配到 crashpad、wxplayer、WeChatAppEx 这些子进程；
  • 托盘项名字靠 PID 拼，这是 KStatusNotifierItem 的命名约定（org.kde.StatusNotifierItem-<pid>-<n>），比猜名字靠谱；
  • 两层兜底：先查托盘管理器，管理器不在就扫总线。托盘管理器由 GNOME 的 ubuntu-appindicators 扩展提供，那个扩展在会话中途被禁用/重载过的话，org.kde.StatusNotifierWatcher 这个名字会暂时消失；
  • ProvideXdgActivationToken 在前，Activate 在后，顺序和 GNOME 那个扩展里的实现一致。纯 Wayland 下没有激活令牌，程序没法把窗口抢到前台；
  • 最后再点一次菜单的「显示」，这相当于绕过所有猜测，直接调用那个确定存在的处理函数。菜单项 id 每个版本可能变，所以按 label 找而不是写死 2。

一点补充

微信里改不了吗？ 改不了。我把 wechat 主程序（一个 173MB 的 ELF）和 /opt/wechat 下所有 so 都扫了一遍 UTF-8 和 UTF-16 字符串，设置相关的只有「开机自启动」，没有「关闭主窗口时最小化到托盘 / 退出程序」这类选项——那是 Windows 版和 macOS 版才有的东西。Linux 版是硬编码：关窗口就隐藏，绝不退出。所以只能从外面兜。

为什么不直接 kill 再启动？ 能恢复，但微信会重新走登录、重新拉会话列表，几分钟的聊天记录同步，代价太大。而且如前所述，单纯再执行一次 /usr/bin/wechat 是无效的。

KDE 能用吗？ 可以。这套逻辑只依赖 StatusNotifierItem 和 dbusmenu，Plasma 原生就提供托盘管理器，脚本不用改。
